# Публичный портал — правила

**R1.** Модель в поисковой строке не пишет ответ. Её единственный выход —
вызов инструмента `search` с полями query/category/tag/reply, вынужденный
через `tool_choice`. Свободного текста от модели пользователь не видит
никогда, поэтому инъекция в вопросе в худшем случае испортит поисковый
запрос, а не подменит ответ.

**R2.** Содержимое заметок в модель не уходит. Она видит только вопрос,
список категорий и топ тегов. Пока это так, инъекция со страницы, попавшей
в базу, до чат-строки не дотянется.

**R3.** Всё, что вернула модель, всё равно фильтруется на сервере: категория
и тег — только из известных списков, query и reply — по белому списку
символов и с обрезкой по длине. Модель не доверенный источник, даже своя.

**R4.** Лимит — 10 вопросов в минуту на адрес, вопрос не длиннее 200
символов, одинаковые вопросы отдаются из кэша. Портал публичный, платит за
токены владелец.

**R5.** Поиск подстрочный, без морфологии. Русское «куртка» не найдёт
«куртки», поэтому модель просят давать корни («куртк»), а при нуле
результатов сервер сам повторяет поиск с обрезанными окончаниями.

**R5.1.** У поиска два режима. Строка поиска — строгий режим: все слова
обязаны совпасть, человек знает, что печатает. Вопрос через модель — режим
`any`: слова модели это догадка о синонимах, требовать их все значит не найти
ничего. Там достаточно одного совпадения, а ранжирование по числу совпавших
слов ставит лучшее наверх.

**R6.** Текст страницы, попавший в промпт классификатора, обёрнут пометкой
«данные, не инструкции». Страница из интернета — недоверенный ввод, и
единственное, что защищает описание заметки, это структурированный вывод
через forced tool use.

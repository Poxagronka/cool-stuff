### Репутация IP важнее, чем кажется

Параллельный прогон с *резидентного* польского IP дал OG-теги на
x.com/instagram/facebook даже с голым `python-requests` UA. То есть нули в
первой таблице — это репутация датацентр-ASN, а не блок по UA.

**Это самый дешёвый рычаг во всей схеме.**

## RU-маркетплейсы: гео в первую очередь

Avito и Яндекс.Маркет с польского резидентного IP отдают буквально
«Доступ ограничен: проблема с IP». Никакая подмена TLS это не лечит — нужен
российский exit.

Плюс с апреля 2026 маркетплейсы перешли от баннера-предупреждения к
**функциональной блокировке VPN-трафика**.

Ни один из четырёх не отдаёт OG анонимному не-RU боту. Для них честнее сдаться:
гео + свой челлендж + ToS = плохой ROI.

## Cloudflare: что изменилось

- **JA4 вытеснил JA3** как отраслевой стандарт (Cloudflare, Akamai, AWS WAF,
  VirusTotal). Причина — рандомизация TLS-расширений в Chrome (GREASE +
  shuffling) сделала сырые JA3-хеши нестабильными; JA4 сортирует расширения
  перед хешированием
- **JA4 Signals** — репутация, привязанная к фингерпринту, а не голый хеш.
  Технически корректный Chrome-JA4, засветившийся в скрейпер-подобном
  поведении, всё равно получает плохой скор. Это добивает «просто подмени JA3»
- `cf-mitigated: challenge` — надёжный программный признак managed challenge
- Managed challenge по умолчанию срабатывает на bot score **2–29**
- **Signed Agents / Web Bot Auth** — легальный путь в allowlist через
  криптографически подписанную идентичность оператора. Для постоянного
  продуктового сервиса превью превращает состязательную задачу в
  административную
- «Please unblock challenges.cloudflare.com» = ваш собственный прокси/DNS режет
  хост виджета Turnstile. Чинить egress, а не челлендж

## TLS-импersonation

**`curl_cffi` 0.16.0 (релиз 2026-08-01)** — безусловный выбор. MIT, 6.2k звёзд,
Python >=3.10. Мейнтейнер сменился с `yifeikong` на `lexiforest`. В 0.16.0:
curl 8.21 + curl-impersonate 2.0, больше HTTP/3-опций, **новая опция порядка
HTTP-заголовков**.

```bash
pip install curl_cffi
```
```python
from curl_cffi import requests
r = requests.get(url, impersonate="chrome", timeout=25)
# async: from curl_cffi.requests import AsyncSession
```

`edge99`/`edge101`, `firefox133/135/144/147`, `safari153…safari2601` + iOS,
`tor145`.

**Использовать безверсионные алиасы** (`"chrome"`, `"safari"`, `"firefox"`) —
они автоматически указывают на свежайший профиль при апгрейде.

### Одного JA3/JA4 в 2026 недостаточно

Нужна когерентность четырёх слоёв одновременно:

1. TLS ClientHello с правильным GREASE
2. HTTP/2 фингерпринт — SETTINGS/WINDOW_UPDATE/дерево приоритетов/порядок
   псевдозаголовков
3. Порядок и регистр HTTP-заголовков (JA4H)
4. Согласованность client hints — `sec-ch-ua` должен соответствовать UA и JA4

Расхождение между слоями само по себе сильный сигнал.

Показательно: **H&M и ASOS оказались завязаны не на TLS, а на полноту
заголовков.** Голый UA давал 403, полный набор Chrome (`sec-ch-ua`,
`sec-fetch-*`, `accept-language`, `br`) давал 200 + OG.

### Лицензионная ловушка

`nodriver` и `zendriver` — **AGPL-3.0**. Встроите в сервис, с которым
пользователи взаимодействуют по сети — сетевая оговорка обяжет открыть
исходники сервиса. Для коммерческого продукта обычно дисквалификация.

**SeleniumBase (MIT) с `--uc --cdp`** даёт тот же CDP-native подход под
пермиссивной лицензией; `patchright` — Apache-2.0.

Проверить это ДО того, как построите пятый тир вокруг nodriver.

## Самая недооценённая оптимизация: обрыв на `</head>`

Замерено на 10 реальных сайтах: средний полный ответ **551 КБ** → ~1900 фетчей
на GB. Но OG-теги живут в `<head>`:

| Сайт | Полностью | До `</head>` |
|---|---|---|
| nytimes.com | 1188 КБ | 200 КБ |
| hm.com | 2116 КБ | **22 КБ** |
| x.com | 288 КБ | **15 КБ** |
| linkedin.com | 341 КБ | **17 КБ** |
| github.com | 387 КБ | 31 КБ |

Средний head — **~47 КБ, в 12 раз меньше**. Стримить ответ и рвать соединение
на `</head>` → **20000+ OG-фетчей на GB** вместо 1900. Плюс gzip/br режет ещё
в 3–4x, а прокси биллят сжатые байты.

**В деньгах: OG-фетч через резидентный прокси $2/GB стоит ~$0.0001 при обрыве
на `</head>` против ~$0.001 при полной загрузке.** Эта одна оптимизация
выгоднее любых переговоров с провайдером.

Headless-браузер, наоборот, тянет JS/CSS/картинки — 2–10 МБ на страницу,
**в 100–500 раз дороже по трафику**. Если браузер неизбежен — резать всё,
кроме document.

## Правовые оговорки

Не юридическая консультация. Фетч публичных OG-тегов для превью — самый
защитимый кейс скрейпинга: это прямое назначение протокола, данные опубликованы
специально для сторонних потребителей, объёмы низкие. Принципиально другая
позиция, чем массовая выгрузка данных.

`robots.txt` не закон, но игнор — доказательство умысла в споре.

Риск концентрируется на **обходе технической меры контроля доступа** (CFAA
в США; в РФ парсинг легален, но отдельно оговорены «программы, обходящие защиту
от парсинга») — программное решение капчи качественно отличается от подмены
User-Agent.

Персональные данные (профили LinkedIn, продавцы Avito) тянут GDPR/152-ФЗ
независимо от публичности.

**Cloudflare Signed Agents / Web Bot Auth — санкционированный путь** для
постоянного идентифицируемого сервиса превью.

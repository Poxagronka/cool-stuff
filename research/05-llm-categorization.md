# Категоризация ссылок через LLM

## Почему LLM, а не правила

Правила по домену работают ровно до момента, когда в чат прилетает ссылка на
Reddit-тред про куртку, статью на Substack про кофеварку и товар на никому не
известном шопе. Домен не говорит ничего. Говорит контекст: заголовок страницы,
og:description и — главное — что люди написали вокруг ссылки в чате.

## Закрытый список категорий

Свободная категоризация даёт помойку из 400 уникальных значений. Нужен
**закрытый список**, который модель обязана соблюдать (enum в схеме):

| Категория | Что попадает |
|---|---|
| `clothing` | одежда, обувь, аксессуары, бренды, шмот-дропы |
| `tech` | железо, гаджеты, девайсы, аудио, фото |
| `software` | приложения, сервисы, библиотеки, репозитории |
| `site` | полезный сайт/инструмент/ресурс сам по себе |
| `article` | статья, лонгрид, видео, подкаст — контент для чтения |
| `food` | еда, напитки, кофе, рецепты, доставки |
| `place` | заведения, города, отели, маршруты |
| `misc` | не подошло никуда |

Восемь — потому что список должен целиком помещаться в голове, когда
фильтруешь. Больше двенадцати не работает.

**Свободные теги — отдельно от категории.** Категория одна, тегов сколько
угодно: `arcteryx`, `gore-tex`, `для-похода`, `дорого`. Категория для
фильтрации, теги для «а что там ещё было про мембраны».

Проверка качества списка: если в `misc` попало больше 10% ссылок — не хватает
категории. Посмотреть, что там скопилось, и добавить одну.

## Что подавать модели

Главная ошибка — скормить только URL и og:description. Половина ссылок в чате
выглядит как «вот» + ссылка. Смысл живёт в соседних сообщениях.

Контекст на одну ссылку:

```
1. URL (канонический) + домен
2. Заголовок страницы, og:description, og:site_name, og:type
3. Текст сообщения со ссылкой
4. Вся reply-цепочка, если сообщение — часть треда
5. Сообщения ±5 минут от того же автора и соседних авторов
6. Автор и дата
```

Пункт 5 — тот, который обычно забывают, и именно он вытаскивает «это на осень,
не на зиму» и «у нас в Польше не продаётся».

## Схема ответа

Structured output через tool use — модель обязана вернуть валидный объект,
парсить текст не надо.

```json
{
  "name": "input_schema",
  "input_schema": {
    "type": "object",
    "properties": {
      "category": {
        "type": "string",
        "enum": ["clothing","tech","software","site","article","food","place","misc"]
      },
      "tags":        {"type": "array", "items": {"type": "string"}, "maxItems": 6},
      "title":       {"type": "string"},
      "description": {"type": "string"},
      "confidence":  {"type": "string", "enum": ["high","medium","low"]}
    },
    "required": ["category","tags","title","description","confidence"]
  }
}
```

Про поля:

- `title` — человеческое имя, не `<title>` страницы. `Arc'teryx Beta LT` вместо
  `Beta LT Jacket Men's | Arc'teryx | Official Online Store EU`
- `description` — **одно предложение своими словами**, включая то, что сказали
  в чате. Копия og:description бесполезна: она уже есть в метаданных, и по ней
  никто не ищет
- `confidence: low` → уходит в инбокс на ручной разбор, а не в общую кучу

## Промпт: что реально важно

- **Дать список категорий с примерами прямо в промпте**, не только в enum.
  Enum обеспечивает валидность, примеры обеспечивают осмысленность
- **Явно разрешить `misc`.** Без этого модель натягивает сову на глобус и
  раскладывает всё по категориям с уверенным видом
- **Явно сказать: описание — на русском, теги — латиницей в kebab-case.**
  Иначе получите половину тегов кириллицей, половину нет, и они не схлопнутся
- **Один вызов = одна ссылка.** Пакетная классификация по 20 штук в одном
  промпте экономит токены, но модель начинает подгонять ответы под соседей и
  теряет ссылки из середины списка
- Батчить надо через Batch API, а не через пихание в один промпт

## Стоимость

Актуальные цены (проверено на `platform.claude.com/docs/en/about-claude/pricing`):

| Модель | Input $/MTok | Output $/MTok | Batch input | Batch output |
|---|---|---|---|---|
| **Sonnet 5** (интро до 2026-08-31) | $2 | $10 | **$1** | **$5** |
| Haiku 4.5 | $1 | $5 | $0.50 | $2.50 |
| Opus 5 | $15 | $75 | $7.50 | $37.50 |

Batch API даёт **-50%**, окно обработки до 24 часов. Для разовой обработки
истории чата это ровно тот кейс, ради которого он существует.

Оценка на 2000 ссылок при ~1200 input / ~150 output токенов на ссылку:

```
input:  2000 x 1200 = 2.4 MTok x $1 = $2.40
output: 2000 x  150 = 0.3 MTok x $5 = $1.50
                                     ------
                                      ~$3.90
```

**Меньше четырёх долларов за разбор полутора лет чата.** Экономить тут не на
чем — не имеет смысла ставить Haiku ради $2 разницы, качество описаний важнее.

Для непрерывного сбора (одна ссылка в момент) Batch не нужен — обычный
синхронный вызов, ~$0.002 за ссылку.

## Prompt caching

Системный промпт со списком категорий и примерами — 500–1500 токенов, одинаков
для всех вызовов. С `cache_control` он читается за 10% цены.

На Batch API кеш и скидка складываются. Экономия небольшая в абсолюте (доллар),
но настраивается одной строчкой.

## Двухпроходный вариант, если качество не устроит

1. Первый проход — все ссылки как есть
2. Собрать реально встретившиеся теги, отсортировать по частоте, взять топ-50
3. Второй проход — те же ссылки, но в промпте список существующих тегов
   с инструкцией «переиспользуй, если подходит; новый заводи только если
   действительно ничего не подходит»

Это лечит главную болезнь свободных тегов: `гортекс` / `gore-tex` /
`goretex` / `мембрана` как четыре разных тега.

Второй проход стоит столько же, сколько первый. Делать только если после
первого видно, что теги расползлись.

## Что НЕ отдавать модели

- **Дедуп.** Это детерминированная задача (см. 02-url-canonicalization.md).
  LLM будет ошибаться в обе стороны
- **Определение мёртвых ссылок.** Это HTTP-статус
- **Дату.** Она есть в метаданных сообщения
